# Shadow Protocol

A multiplayer encrypted strategy game on Ethereum Sepolia, powered by Zama FHEVM. Two to four players bid for artifacts over five rounds. Every move (action, bid, tactic power, target) is an FHE ciphertext, so rivals can never read your strategy, yet the contract still settles every round.

## The game

- 2 to 4 players, 5 rounds, 1,000 starting credits, +100 income per round you play.
- Each round has a public artifact worth 2 to 6 points (schedule derived from a verified seed).
- Every round you seal one encrypted move:
  - **Bid**: sealed first-price bid. Winner pays its bid; everyone else keeps their credits.
  - **Shield**: bid and burn credits to absorb incoming sabotage.
  - **Sabotage**: bid and burn credits to cut a rival's bid (after their shield). A bad guess wastes the credits.
  - **Double**: stake at least half your bid. Win: 2x points and the stake back. Lose: stake burned and minus 1 point.
  - **Pass**: spend nothing, earn a 150 credit rest bonus.
- Bids are clamped to the credits you really hold. Ties go to the first player in a start order that rotates every round.
- Miss a round and you are auto-passed with no income. Miss 3 and you can no longer win the prize.
- Highest score after round 5 wins. Ties share the prize.

Gameplay credits are not a financial asset. The optional prize is separate (confidential cUSDT).

## What is encrypted, public and verifiable

| | |
|---|---|
| Encrypted | action, bid, power, target, credit balances, scores until the end, all intermediate maths |
| Public | who joined, who sealed a move (not what), deadlines, phase, artifact schedule after the seed is revealed, round winner slot, final scores, missed-round counters |
| Verifiable | the artifact seed is generated by the FHE coprocessor and accepted onchain only with a valid KMS signature; final scores likewise; rules are open Solidity; sealed moves cannot be changed |

Limits worth knowing: transactions still reveal that a player acted and when. One person controlling several wallets in a match can coordinate against it. The seed is produced by Zama's coprocessor and KMS, so fairness relies on Zama's threshold trust assumptions.

## Architecture

| Layer | Where |
|---|---|
| State, lobby, seed, finalization, views | `contracts/ShadowProtocol.sol` |
| Encrypted round engine, prize escrow and claims (reached by delegatecall) | `contracts/ShadowRounds.sol` |
| Shared storage, events, errors, artifact rules | `contracts/ShadowStorage.sol` |
| cUSDT (ERC-7984) interfaces | `contracts/interfaces/IConfidentialToken.sol` |
| Test-only confidential token | `contracts/mocks/MockConfidentialToken.sol` |
| FHE tests (Zama Hardhat plugin) | `fhe/test/ShadowProtocol.test.ts` |
| Frontend | `src/` (React, Vite, wagmi, ConnectKit, Tailwind, Framer Motion) |
| Zama SDK wrapper | `src/lib/fhe.ts` (WASM files served from `public/`, copied from the SDK `bundle/` folder) |

The contract is split in two only because Sepolia charges roughly 1,500 gas per byte of deployed code, which a single 19 KB contract could not afford. Clients talk to the `ShadowProtocol` address with the merged ABI in `abi/ShadowProtocol.merged.json`.

### Confidential rewards (cUSDT)

The prize token is set once in the `ShadowProtocol` constructor. This deployment uses Zama's documented Sepolia test wrapper `cUSDTMock` at `0x4E7B06D78965594eB5EF5414c357ca21E1554491` (underlying test USDT `0xa7dA08FafDC9097Cc0E7D4f113A61e31d7e8e9b0`, publicly mintable). Source: https://docs.zama.org/protocol/protocol-apps/addresses/testnet/sepolia

Flow: the match creator escrows an encrypted prize with `confidentialTransferAndCall` (the UI does this and can mint and wrap test tokens). After the match, winners call `claimPrize`; if nobody was eligible the creator reclaims the escrow with `claimRefund`. Payments are pull-based so a failing token can never freeze a match.

Configuration point for another network or the official mainnet cUSDT: pass its ERC-7984 wrapper address as `PRIZE_TOKEN` to `scripts/deploy-sepolia.sh` (or the constructor). The official Ethereum mainnet cUSDT is listed at https://www.zama.org/confidential-tokens. Mainnet is not deployed or tested here.

## Development

Prerequisites: [Bun](https://bun.sh), [Foundry](https://getfoundry.sh), Node 20+, a browser wallet on Sepolia.

```bash
bun install
cp .env.example .env     # fill in the public values below
bun run dev              # http://localhost:5173
bun run build
bun run check            # lint + typecheck
```

### Environment variables

| Name | Purpose |
|---|---|
| `VITE_SHADOW_PROTOCOL_ADDRESS` | Deployed ShadowProtocol address on Sepolia |
| `VITE_SHADOW_DEPLOY_BLOCK` | Block of that deployment (start of event scans) |
| `VITE_PRIZE_TOKEN_ADDRESS` | Confidential reward token (ERC-7984 wrapper) |
| `VITE_PRIZE_UNDERLYING_ADDRESS` | Underlying test token, used by "Get test cUSDT" |
| `VITE_SEPOLIA_RPC_URL` | Sepolia RPC endpoint (optional, defaults to a public one) |
| `DEPLOYER_PRIVATE_KEY` | Deploy and smoke scripts only. Never put it in a `VITE_` variable |
| `SEPOLIA_RPC_URL` | Deploy and smoke scripts only (optional) |

### Tests

```bash
bun run test:fhe         # 33 FHE tests in Zama's Hardhat environment (real FHE library, mock coprocessor)
bun run contracts:build  # forge build
```

Covered: match creation, joining, 2 and 4 player limits, seed verification, encrypted submissions, wrong-user and malformed inputs, access control on balances, encrypted comparisons, shield, sabotage, double, pass, ties, timeouts, duplicates, disconnected players, disqualification, final score verification, prize claims and refunds.

The mock coprocessor does not prove production behavior, so a live check is included:

```bash
DEPLOYER_PRIVATE_KEY=0x... bun run smoke:sepolia   # plays one real encrypted round on Sepolia
```

### Deploy your own copy

```bash
DEPLOYER_PRIVATE_KEY=0x... bun run deploy:sepolia
```

The script deploys with your own funded testnet key because each contract needs about 16M gas on Sepolia. Then set the two `VITE_SHADOW_*` values in `.env`.

### Verify on Etherscan

```bash
forge verify-contract <address> contracts/ShadowRounds.sol:ShadowRounds --chain sepolia --etherscan-api-key $ETHERSCAN_API_KEY
forge verify-contract <address> contracts/ShadowProtocol.sol:ShadowProtocol --chain sepolia --etherscan-api-key $ETHERSCAN_API_KEY \
  --constructor-args $(cast abi-encode "constructor(address,address)" <prizeToken> <roundsAddress>)
```

Contracts are not verified on Etherscan yet.

### Frontend deployment

`bun run build` outputs a static site in `dist/`. Host it on any static host (Netlify, Vercel, Hugging Face static Space) and set the `VITE_*` variables there. Send route fallbacks to `index.html`.

## Honest status

- The frontend has not been exercised in a browser with a wallet. The contracts and the SDK flow were exercised live on Sepolia through `scripts/smoke-sepolia.mjs`.
- Round timing assumes the Zama relayer and KMS are reachable; when they are slow the UI retries public decryption.
- Not audited by a third party.
